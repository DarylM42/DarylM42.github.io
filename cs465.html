Artifact Overview

What Is This Artifact?

The CS-465 artifact is a full-stack travel booking web application built with the MEAN stack MongoDB as the document database, Express.js as the RESTful API layer, Angular as the single-page application frontend, and Node.js as the server runtime. The application was originally developed during the CS-465 Full Stack Development course, where it served as a vehicle for learning MEAN-stack fundamentals: routing, CRUD operations, data modeling, and API consumption.

In its original state the application provided core booking functionality but lacked any meaningful authentication or authorization layer. Any user with network access could invoke administrative API endpoints directly, bypassing the frontend entirely. User credentials were stored in plaintext, and no input validation prevented malformed or malicious data from reaching the database.

This artifact was selected for the ePortfolio because it provides a rich surface area for demonstrating software engineering and design competencies specifically, architectural refactoring, secure authentication design, and the application of industry-standard security middleware.

Enhancement Narrative

Why These Enhancements?

Justification for Inclusion

I selected the CS-465 Full Stack Application for this artifact category because it represents the most realistic simulation of a production-grade web application in my academic work. The MEAN stack is widely used in industry, and the gap between the original artifact and a deployable, secure application was significant enough to produce meaningful, demonstrable enhancements. This project showcases my ability to take a functional but insecure application and elevate it to a professionally defensible state.

What Was Enhanced and Why

Authentication Architecture. The original application had no login system all routes were publicly accessible. I designed and implemented a complete JWT-based authentication flow. When a user successfully authenticates, the server issues a signed JSON Web Token containing the user's ID and role. Subsequent requests include that token in the Authorization: Bearer header. A custom Express middleware validates the token's signature and expiry on every protected route before the request reaches the controller. This is stateless, horizontally scalable, and aligned with the OAuth 2.0 ecosystem that dominates modern web APIs.

Password Security. The original code stored user passwords in plaintext a critical vulnerability that would expose every account if the database were breached. I replaced this with bcrypt hashing (salt rounds = 12). Hashing happens in a Mongoose pre-save hook so the plaintext password never touches the controller layer and is never logged or transmitted after the initial registration request.

Role-Based Access Control. Beyond authentication (verifying who you are), the application needed authorization (verifying what you are allowed to do). I defined three roles admin, editor, and viewer and created a composable authorize() middleware factory. Routes requiring elevated privileges declare the permitted roles explicitly: router.delete('/trips/:id', authenticate, authorize('admin'), tripsController.delete). This single-line declaration pattern makes access control auditable at a glance.

Input Validation. The original controllers accessed request body properties directly with no validation. A malicious actor could submit unexpected types, oversized strings, or operator injection payloads. I introduced Joi schemas for every API input surface. The validation middleware rejects non-conforming requests with structured 400 error responses before data reaches the database layer.

HTTP Security Headers. Helmet.js was added as the first middleware in the Express pipeline. This automatically sets a suite of response headers Content Security Policy, HTTP Strict Transport Security, X-Content-Type-Options, X-Frame-Options, and Referrer-Policy — that defend against a wide class of web vulnerabilities including clickjacking, MIME-sniffing, and cross-site scripting.

Reflection: What I Learned

The most significant learning from this enhancement was experiencing first-hand how security concerns permeate every layer of a full-stack application. I initially planned to add authentication at the route level only, but quickly realized that password handling required changes at the model level, role enforcement required changes at the middleware level, and frontend Angular guards required changes at the client level. Security is not a feature you bolt on it is a cross-cutting concern that must be considered throughout the architecture.

I also encountered practical challenges around token expiry and refresh flows. Deciding on an appropriate token lifetime balancing security (shorter = better) with usability (longer = better for user experience) required me to research industry standards and ultimately implement a 15-minute access token paired with a 7-day refresh token stored in an HttpOnly cookie. This decision reflects professional engineering judgment, not just technical implementation.

Code Sample

JWT Authentication Middleware

The following middleware demonstrates the core of the authentication enhancement. It extracts and verifies the JWT on every protected request, attaches the decoded payload to req.user, and passes control to the next handler or returns a structured 401/403 response if verification fails.

// middleware/auth.js
const jwt = require('jsonwebtoken');
const User = require('../models/user');

/**
* authenticate verifies the Bearer JWT on every protected route.
* Attaches decoded payload to req.user for downstream middleware.
*/
const authenticate = async (req, res, next) => {
  try {
    const header = req.headers.authorization;
    if (!header || !header.startsWith('Bearer ')) {
      return res.status(401).json({ error: 'Authorization header missing or malformed' });
    }

    const token = header.split(' ')[1];
    const decoded = jwt.verify(token, process.env.JWT_SECRET);

    // Confirm user still exists in the database
    const user = await User.findById(decoded.id).select('-password');
    if (!user) return res.status(401).json({ error: 'User no longer exists' });

    req.user = user;
    next();
  } catch (err) {
    const msg = err.name === 'TokenExpiredError'
      ? 'Token has expired — please log in again'
      : 'Invalid token';
    return res.status(401).json({ error: msg });
  }
};

/**
* authorize — factory that returns a middleware enforcing allowed roles.
* Usage: router.delete('/trips/:id', authenticate, authorize('admin'), handler)
*/
const authorize = (...roles) => (req, res, next) => {
  if (!roles.includes(req.user.role)) {
    return res.status(403).json({
      error: `Role '${req.user.role}' is not authorized for this action`
    });
  }
  next();
};

module.exports = { authenticate, authorize };
